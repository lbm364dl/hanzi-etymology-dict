# HSK 1 checkpoint: DNS recovery and review contracts

The latest full published-entry validation counted 214/300 ready HSK characters.

## Network incident and recovery

Thirteen terminal jobs were interrupted by DNS failures resolving the model endpoint.
Their stderr logs recorded failed address lookups, and the subprocesses eventually
reached their existing ten-minute timeout. A subsequent host lookup succeeded, and
new jobs produced completed stage outputs again. These were transport failures,
not editorial rejections.

The recovery manifest identifies the exact terminal jobs. It preserves their original
failure statuses and resumes their original run/refine inputs in the same directories,
letting the existing exact-input cache reuse completed stages. It does not manufacture
reviews or approve interrupted outputs. The completed recovery yielded approvals for
视、书、太、岁、体、那; the other characters retained actual revision findings and
received targeted follow-ups.

## Contract repair

One factual verifier returned `revise` while saying that its alleged reading correction
was already correct and no correction was needed. The harness now requests one more
actual review when a revise finding explicitly says no correction/change is needed.
That reviewer must identify real required changes or return pass with no findings.
The coordinator never converts the verdict itself. Repeated contradictory output
fails the stage and cannot publish.

The regression covers both a genuine third-review pass and a repeated invalid verdict;
it checks the actual reviewer identity and the bounded three-call sequence. All 96
pipeline tests pass.
