# Select remaining source work across batch folders

An attempted 好 continuation accidentally prepared 爱 because the harness selected
from the start of the full cohort in a fresh output folder. No research ran for
that mistaken target; its prepared artifacts remain preserved. More generally,
source enrichment previously skipped completion only inside the requested folder,
so a new folder could redo characters verified in an earlier batch. This impedes
the actual 300-entry objective and is independent of any character's etymology.

`status`, `prepare` and `run` now use the existing full-cohort source-progress
verifier across canonical run locations and the requested output. A character is
skipped only when a current exact source/publication gate passes. The returned job
path points to that real verified job; no approval or new source snapshot is
copied. Stale metadata, unresolved source findings, another source and legacy
approval alone cannot skip work. The selection limit counts remaining entries.

The regression exercises actual publication/hash gates in the fixture: all three
entry points reuse an earlier folder without preparing a new snapshot; the next
unfinished entry consumes the limit; another book, pending source findings and
stale hashes are not reused. Source-enrichment and source-progress tests pass
(24 tests). A read-only real full-cohort status check against a fresh nonexistent
output folder finds 17 published / 283 pending, matching the authoritative audit.
It names 八、爸、吧、白、百、班、帮、包 as the next unverified entries; no new
research batch was started while 好 and 学 repairs remain active.

Additional registered books use the same mechanism with their own source IDs and
provenance. This does not import an old book's research as verification for a new
book, or assert any entry has completed a source merely because it was published.
